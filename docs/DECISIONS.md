# Решения по архитектуре

Append-only лог. Существующие записи не редактируются и не удаляются:
изменение решения оформляется новой записью с новой датой.

## 2026-10-30 — Лицензия GPL-3.0-only

**Решение:** Проект распространяется под GPL-3.0-only.

**Причина:** Пользователь хочет copyleft. MIT/Apache-2.0 зависимости совместимы
односторонне.

## 2026-10-30 — Команды как отдельные крейты

**Решение:** Каждая команда — отдельный крейт в `commands/*`, зависящий от
`jarvis-core` по path.

**Причина:** Будущий вынос в dylib (libloading) без рефакторинга ядра.

## 2026-10-30 — LLM вне ядра

**Решение:** LLM не входит в ядро, а подключается отдельным плагином позже.

**Причина:** Ядро должно работать офлайн и без тяжёлых зависимостей.

## 2026-10-30 — TTS на стороне пользователя

**Решение:** Синтез речи не реализуется в проекте, мы только плеер (rodio).

**Причина:** Не тащим синтез речи в open-source проект.

## 2026-10-30 — Заметки в JSON, не SQLite

**Решение:** `note` хранит заметки в JSON-файле.

**Причина:** MVP, нет смысла тянуть rusqlite ради десятка заметок.

## 2026-10-30 — Память между сессиями агента

**Решение:** Контекст между сессиями агента передаётся через `STATE.md`,
`TASKS.md` и `DECISIONS.md`, а не перечитыванием всего репозитория.

**Причина:** Экономия токенов и сохранение контекста.

## 2026-10-30 — Целевые платформы v0.1

**Решение:** Поддерживаемые платформы v0.1 — Linux и Windows.

**Причина:** Остальные платформы не тестируются и не заявляются.

## 2026-10-31 — Path-зависимость команд к ядру

**Решение:** В `crates/commands/*/Cargo.toml` использовать
`jarvis-core = { path = "../../jarvis-core" }` (не `../..`).

**Причина:** Крейты команд лежат в `crates/commands/<name>/`, корень репо —
виртуальный workspace-манифест без пакета. `../..` даёт путь в `crates/`,
где пакета `jarvis-core` нет; оттуда же `../../crates/jarvis-core` вёл бы в
несуществующий `crates/crates/jarvis-core`.

## 2026-10-31 — Набор команд v0.1

**Решение:** open, weather, volume, note (не time).

**Причина:** SPEC v0.1 перечисляет именно эти четыре.

## 2026-10-31 — rust-version в workspace

**Решение:** `rust-version = "1.75"`.

**Причина:** В ТЗ bootstrap было 1.75; агент поставил 1.74 — вернули к 1.75.

## 2026-10-31 — Multi-provider LLM, опциональная

**Решение:** LLM подключается как опциональный плагин через трейт `LlmProvider`.
В `Context` — `Option<Arc<dyn LlmProvider>>`. Провайдеры (cloud/local) —
отдельные крейты, регистрируются в фабрике по ключу `config.llm.provider`.
Без настроенной LLM Джарвис полностью работоспособен (только команды,
без интернета).

**Причина:** (1) Ядро остаётся лёгким и офлайновым. (2) Пользователь выбирает:
только команды / локальная модель / облако. (3) Смена провайдера — правка
одного поля в `config.toml`, без изменения кода. (4) Новый провайдер —
изолированный крейт ~200 строк, без рефакторинга ядра.

## 2026-10-31 — Ключи API только через ENV

**Решение:** В `config.toml` — только имя переменной окружения (`api_key_env`).
Реальный ключ хранится в shell/OS env (например `MISTRAL_API_KEY`), не в
конфиг-файле.

**Причина:** Защита от случайной утечки ключей в git/gist при коммите
`config.toml`. Совпадает с практикой gh, aws-cli, docker.

## 2026-10-31 — Переопределение трейта Command
**Решение:** В Command добавлены `matches(&str)` и
`async run(&str, &Context) -> Result<Output>`; `execute()` удалён.
Добавлены `Output { text, speech }` и `enum Speech { File, Bytes }`.
**Причина:** Диспетчер должен матчить по вводу и выполнять команду
с контекстом. Старая сигнатура не позволяла ни того, ни другого.
`Speech` заложен под будущий TTS-плеер, сейчас поле всегда None.

## 2026-10-31 — Зависимости webbrowser и urlencoding
**Решение:** Добавлены `webbrowser = "1"` (~50 КБ) и
`urlencoding = "2"` (~30 КБ, без зависимостей).
**Причина:** webbrowser кроссплатформенно открывает URL (Linux/
Windows/macOS), не тащить open/xdg-open вручную. urlencoding —
для percent-encode поисковых запросов; ручной цикл даёт баги
на кириллице и `&`/`?` в запросе.

## 2026-10-31 — REPL на std::io, без rustyline
**Решение:** Первый REPL — `std::io::stdin().read_line()`.
**Причина:** Минимум зависимостей на старте. rustyline добавим
отдельной сессией, когда понадобится история/редактирование.

## 2026-10-31 — Поиск через DuckDuckGo в cmd-open
**Решение:** `open <не-URL>` (нет точки или есть пробелы) идёт
в https://duckduckgo.com/?q=<urlencoded>.
**Причина:** Без этого `open` — обёртка над xdg-open/start, которая
уже есть в системе. С поиском одна команда закрывает и «open youtube»,
и «open rust было», и «open https://ya.ru».

## 2026-10-31 — Зависимость async-trait
**Решение:** Добавлен `async-trait = "0.1"` в workspace и в
`jarvis-core`/команды; трейт `Command` объявлен через
`#[async_trait::async_trait]`.
**Причина:** Стабильный Rust не умеет `async fn` в трейтах объектов
(`dyn Command`). `async-trait` — де-факто стандарт (используется axum,
tower), макрос-трансформер без рантайма. Альтернатива — ручной
`Pin<Box<dyn Future>>` в каждой реализации, больше шума.

## 2026-10-31 — Зависимости fastrand, reqwest, serde_json
**Решение:** fastrand = "2" (jarvis-core, для persona);
reqwest = { json, rustls-tls } (cmd-weather); serde_json = "1"
(cmd-weather).
**Причина:** fastrand (~10 КБ, без зависимостей) — рандом фраз
persona. reqwest+rustls-tls — HTTP без openssl на Linux.
serde_json — парсинг open-meteo.

## 2026-10-31 — Провайдер погоды open-meteo
**Решение:** weather через open-meteo (geocoding + forecast),
парсинг через serde_json::Value (без структур).
**Причина:** Бесплатно, без ключа, стабильный JSON, покрывает
города по имени. Структуры — избыточны для двух полей, MVP.

## 2026-10-31 — persona как модуль jarvis-core
**Решение:** Фразы в jarvis-core/src/persona.rs, пулы
&'static [&'static str], рандом через fastrand.
**Причина:** Ответы в стиле Джарвиса нужны всем командам.
Хардкод-константы на старте; TOML/LLM — позже.

## 2026-10-31 — Fallback на wttr.in в cmd-weather
**Решение:** Если open-meteo недоступен (сеть/блокировка),
пробуем https://wttr.in/{city}?format=j1 как второй провайдер.
**Причина:** api.open-meteo.com заблокирован в ряде регионов
(РФ), geocoding работает, forecast — таймаутит. wttr.in даёт
температуру и описание без ключа, как fallback достаточно.
Формат ответа одинаковый, пользователь не видит разницы.

## 2026-10-31 — Русские описания в wttr.in
**Решение:** lang=ru в запросе к wttr.in.
**Причина:** Без него описания на английском ("Overcast"),
что не в стиле Джарвиса. lang=ru даёт русский текст без
дополнительных зависимостей.
**Уточнение:** в JSON `format=j1` перевод приходит не в
`weatherDesc`, а в `current_condition[0].lang_ru[0].value`
(`weatherDesc` остаётся английским). Берём `lang_ru`, затем
`weatherDesc`, пустая строка → «неизвестно».

## 2026-10-31 — Vosk как первый STT-провайдер

**Решение:** Голосовой ввод через Vosk (крейт `vosk` 0.3), офлайн,
модель `vosk-model-small-ru-0.22`. Путь к нативной библиотеке при
сборке можно задать через `VOSK_LIB_DIR` (читает `build.rs` крейта
`jarvis-stt-vosk`), по умолчанию — системные пути линковщика.

**Причина:** Бесплатно, без ключей, работает офлайн, ~45 МБ модель,
достаточно для команд. Google/Whisper — опционально позже, через
тот же трейт `SpeechToText`.

## 2026-10-31 — Трейт SpeechToText в jarvis-core (Вариант A)

**Решение:** Трейт `SpeechToText` и `SttConfig` живут в `jarvis-core`
(модуль `stt.rs`). Реализации — в отдельных крейтах
(`jarvis-stt-vosk` и будущие). `jarvis-core` НЕ зависит от
`jarvis-stt-vosk`. Фабрики `build_*` живут в крейтах-реализациях.

**Причина:** Избежать циклической зависимости core ↔ stt. Core не
знает про Vosk, только про абстракцию. Общая фабрика по provider
появится при втором провайдере.

## 2026-10-31 — libvosk не коммитим

**Решение:** Нативная библиотека и модели — ответственность
пользователя, не репозитория. Не добавляем автоматическое скачивание.

**Причина:** Бинарники раздувают репо, ломают CI, зависят от ОС.
Линковка `vosk` статическая на этапе сборки: без `libvosk.lib` /
`libvosk.so` проект не собирается, а без DLL/SO в путях загрузчика
не запускается. Это ограничение библиотеки, не наше.

## 2026-10-31 — cpal для записи

**Решение:** `jarvis-audio` получает `cpal = "0.15"` для захвата
с микрофона через `record_until_silence` (RMS-порог, без VAD).

**Причина:** Кроссплатформенный (Linux/Windows/macOS), минимальный,
не тянет ML-модели для VAD. Частота устройства приводится к
запрошенной линейной передискретизацией.

## 2026-10-31 — Загрузка config.toml

**Решение:** `Config::load` + `toml = "0.8"`; CLI читает
`config.toml` из текущего каталога, при ошибке печатает
предупреждение и берёт `Config::default()`. В репозитории —
`config.example.toml`, сам `config.toml` в `.gitignore`.

**Причина:** без загрузки TOML секция `[stt]` (и `[weather]`)
недостижима из файла, а README обещает настройку через
`config.toml`. `toml` — стандартный парсер, ~3 транзитивные
зависимости.

## 2026-10-31 — Контекст хранит готовый STT

**Решение:** В `Context` добавлено
`stt: Option<Arc<dyn SpeechToText>>`; `Context` остаётся `Clone`
(Arc клонируется дёшево). `Debug` реализован вручную, чтобы не
требовать `Debug` от трейт-объекта.

**Причина:** команды получают провайдера из контекста и не знают,
как он создан. Ошибка инициализации STT не роняет CLI: поле
остаётся `None`, `listen` возвращает понятную ошибку.

## 2026-10-31 — Feature flag vosk в jarvis-cli

**Решение:** Vosk-интеграция — опциональная фича cargo
(`[features] default = []; vosk = ["dep:jarvis-stt-vosk"]`),
по умолчанию выключена. `listen` зарегистрирован всегда: без фичи
`run()` возвращает понятную ошибку, с фичей работает как раньше.

**Причина:** Статическая линковка `libvosk` (`vosk-sys`) требует
`VOSK_LIB_DIR` на этапе сборки и DLL в `PATH` на этапе запуска.
Без feature flag `clone → cargo build` падает у любого, у кого нет
Vosk. Для OSS это недопустимый барьер входа. С флагом обычная
сборка работает без нативных зависимостей, а
`--features vosk` даёт полную функциональность.

## 2026-10-31 — Wake word «Джарвис» через Vosk с грамматикой

**Решение:** Wake word detection — отдельный крейт `jarvis-wake`
(`WakeWordDetector`): Vosk `Recognizer` с грамматикой
`["джарвис", "джарвиз", "jarvis", "[unk]"]`, микрофон читается
потоково через `jarvis_audio::record_stream`. Голосовой режим
(`voice` в `jarvis-cli`): `wait_for_wake` → `record_until_silence` →
`transcribe` → `dispatch`. Выход — распознанные «стоп» / «хватит» /
«выход» / «exit».

**Причина:** Vosk уже в проекте, отдельные wake-word-движки
(rustpotter, Porcupine) не нужны: Porcupine проприетарный и требует
ключ/обучение модели, rustpotter — ещё одна модель и ещё одна
зависимость. Грамматика ограничивает распознавание только
обращениями, `[unk]` забирает всё остальное. «Джарвис» должно быть
слышно отдельно от команды (как у Алисы), иначе грамматика,
ограниченная wake-словами, не распознает саму команду.

**Ограничение:** грамматика Vosk строится по словарю модели; если
слова «джарвис» в словаре нет, распознавание опирается на `[unk]` и
акустически близкие слова. Живой тест с микрофоном/моделью — на
стороне пользователя.

## 2026-10-31 — Mistral LLM как опциональный провайдер и умный роутинг

**Решение:** LLM — опциональный провайдер за трейтом
`jarvis_core::llm::LlmProvider` (реализация — крейт
`jarvis-llm-mistral`, модель `mistral-small-latest`). Включается
секцией `[llm]` в `config.toml`; ключ API читается **только из
переменной окружения** (`api_key_env`, по умолчанию
`MISTRAL_API_KEY`). Выбор между командой и LLM автоматический: в
REPL и в `voice` сначала идёт `dispatcher.dispatch` (`matches()`
команд), и только если ни одна команда не подошла — запрос в LLM.
Команда `ask <вопрос>` принудительно отправляет вопрос в LLM.

**Причина:** команды остаются детерминированными и бесплатными, а
свободный текст получает осмысленный ответ. Порядок «сначала
команды» гарантирует, что «погода» не уйдёт в сеть как вопрос к
LLM. Ключ в файлах проекта не хранится: утечка ключа в репозиторий
— типовая ошибка, а `config.toml` лежит рядом с кодом. Без ключа
или без секции `[llm]` `jarvis` работает только командами, то есть
LLM не становится обязательной зависимостью для OSS.

**Ограничения:** истории диалога нет (каждый вопрос отдельный), нет
стриминга, таймаут 30 с, ошибки API показываются в персонаже.

## 2026-10-31 — native-tls вместо rustls для reqwest

**Решение:** в `[workspace.dependencies]` reqwest собирается с
`features = ["json", "native-tls"]` вместо `["json", "rustls-tls"]`.

**Причина:** rustls давал ошибки TLS при обращении к API Mistral.
`native-tls` использует системный стек: Schannel на Windows и
OpenSSL на Linux — он дружит с системными и корпоративными
сертификатами и не требует отдельного набора корневых. Цена: на
Linux для сборки нужны заголовки OpenSSL (`pkg-config`,
`libssl-dev`) — это добавлено в README. Для Windows новых
зависимостей, кроме `schannel`, нет.

## 2026-10-31 — Полная цепочка сетевых ошибок

**Решение:** ошибки `reqwest`/`serde_json` оборачиваются через
`anyhow::Context::context`, а не через `map_err(|e| anyhow!("…:
{e}"))`.

**Причина:** `map_err` со строкой схлопывал источник, и в REPL
оставалось «error sending request for url (…)» без причины. С
`context` anyhow хранит цепочку источников, а формат `{e:#}`
(уже используется в REPL и в персонаже) печатает её целиком:
таймаут, DNS, TLS или отказ hyper.

## 2026-10-31 — Модель LLM задаётся в конфиге

**Решение:** в `LlmConfig` добавлено необязательное поле
`model: Option<String>`; `MistralClient` получил поле `model` и
разрешает модель по приоритету: аргумент `complete()` → модель
клиента → `mistral-small-latest`. Пустая строка считается
«не задано». `build_mistral` пробрасывает `cfg.model` в клиент.

**Причина:** разные задачи требуют разной модели (быстрая дешёвая
против большой), а хардкод `mistral-small-latest` заставлял
пересобирать проект. Поле опционально, поэтому старые конфиги
работают без изменений.

**Проверка:** приоритет закреплён юнит-тестом `model_priority` в
`jarvis-llm-mistral` (без сети).

## 2026-10-31 — System prompt и протокол `__CMD__:`

**Решение:** в `LlmConfig` добавлено поле `system_prompt: Option<String>`
(публичный API `jarvis-core` расширен). По умолчанию — константа
`DEFAULT_SYSTEM_PROMPT` с ролью Джарвиса и правилом: на просьбу о
действии возвращать ровно одну строку `__CMD__:<команда>`, а не
объяснение. Пустая строка отключает промпт. `MistralClient` получил
поле `system_prompt` и отправляет его первым сообщением с ролью
`system`; `build_mistral` пробрасывает `cfg.system_prompt`. CLI в REPL
и в голосовом режиме проверяет префикс `__CMD__:` **до** обычного
вывода и отдаёт команду `Dispatcher`; `ask` из ответа LLM не
выполняется (защита от рекурсии). Команда `ask` возвращает такой ответ
как есть, выполнение делает вызывающая сторона.

**Причина:** модель может «поговорить» о том, как открыть сайт, но не
может нажать кнопку. Строковый маркер — самый простой контракт без
tool-calling API и без парсинга JSON: одна проверка префикса, работает
с любой моделью Mistral. Поле опционально и с дефолтом, поэтому старые
конфиги работают без изменений.

**Проверка:** юнит-тесты `jarvis-core` (дефолт/переопределение/пустая
строка) и `jarvis-llm-mistral` (`system_prompt_goes_first`,
`empty_or_missing_system_prompt_is_skipped`) идут без сети.

## 2026-10-31 — Короткие имена сайтов в cmd-open

**Решение:** `cmd-open` перед поиском в DuckDuckGo сверяет ввод с
таблицей известных сайтов (`ютуб`/`youtube` → `https://www.youtube.com`,
а также google/яндекс/вк/github/telegram/википедия). Остальное — как
раньше: URL, домен с точкой или поиск.

**Причина:** системный промпт приводит пример «открой ютуб» →
`__CMD__:открой ютуб`. Одно слово без точки уходило в поиск DDG вместо
сайта, и обещанное «Открываю youtube.com» не выполнялось. Таблица
маленькая и явная; расширять её — по мере надобности.

**Проверка:** юнит-тесты `cmd-open` (`known_sites_open_directly`,
`urls_and_domains_are_kept`, `the_rest_goes_to_search`).

## 2026-11-01 — Аудиосопровождение на rodio и локальные файлы

**Решение:** `jarvis-audio` проигрывает готовые файлы через
`rodio = "0.19"` с `default-features = false, features = ["mp3"]`
(mp3 декодирует symphonia). Звуки — обычные файлы в `assets/audio/`;
`greeting.mp3` играет при старте, `success.mp3` — после успешно
выполненной команды, плюс есть команда `speak <путь>`. Файлы
опциональны: нет файла или звуковой карты — REPL работает молча.

**Причина:** TTS в проекте не реализуется (см. запись 2026-10-30),
нужен только плеер. Локальные файлы не требуют сети и работают
офлайн. rodio кроссплатформенный и использует cpal 0.15 — тот же,
что уже есть у записи. `default-features = false` оставляет только
mp3-декодер, без flac/vorbis/wav (меньше зависимостей). Проигрывание
блокирующее и вызывается через `tokio::task::spawn_blocking`, чтобы
не вешать REPL.

**Ограничения:** громкость отдельно не регулируется, очереди и истории
звуков нет, voice ducking нет — микрофон в `voice` слышит собственную
озвучку (это уже отмечено в STATE.md).
